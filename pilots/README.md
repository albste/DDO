# Pilots

How a community can run a pilot of DDO.

1. **Read the limits.** The documents are a draft and the technical specification has not been security-reviewed. Do not use them for binding elections. Start with advisory and delegated decisions.
2. **Run a founding vote.** All adult citizens in good standing of the community vote with equal weight, no domain scores, simple majority with quorum. Use [founding-vote-template.md](founding-vote-template.md).
3. **Set your own gates.** The participants decide the criteria for moving between phases. A failed gate means staying in the phase or stepping back.
4. **Define stop criteria.** Pause or reverse the pilot if an audit finds an unresolved critical flaw, if participation falls below the level participants set, or if a group has captured the system.
5. **Publish results.** Results of different pilots are published and compared, including failures.
6. **Provide access.** Nobody loses their vote for lack of a device: offer kiosks, assisted voting and offline enrolment.
